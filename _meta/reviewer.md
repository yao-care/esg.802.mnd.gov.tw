# Meta-Reviewer：閉環完備性判斷標準

本檔案定義 stub 判定標準、文件類型特定關鍵字，以及閉環完備性驗證的通用 checklist。所有 reviewer 在執行文件審查前，必須先閱讀本檔案。

---

## 1. Stub 判定標準

### 1.1 rule.md stub 判定（RC-2）

符合以下**任一**條件即判定為 stub，須拒絕合併：

- [ ] 含「待補充」「TBD」「TODO」「FIXME」等佔位符
- [ ] 不含任何「【必要】」標記
- [ ] 缺少「必要章節結構」「語氣與用詞規範」「必要元素」「交叉引用規則」「審查重點」五個區段之任一
- [ ] 全文字數少於 200 字（stub 通常極短）

### 1.2 writer.md stub 判定（RC-3）

符合以下**任一**條件即判定為 stub：

- [ ] 含「待補充」「TBD」「TODO」「FIXME」等佔位符
- [ ] 不含「rule.md」引用或參照
- [ ] 不含「必要章節結構」相關說明
- [ ] 不含 ESG 術語規範或寫作風格說明

### 1.3 reviewer.md stub 判定（RC-4）

符合以下**任一**條件即判定為 stub：

- [ ] 含「待補充」「TBD」「TODO」「FIXME」等佔位符
- [ ] checkbox 數量 ≤ 10（實質 reviewer 通常遠多於此）
- [ ] 不含任何類型特定關鍵字（見第 4 節）
- [ ] 所有 checkbox 與其他類型的 reviewer.md 完全相同（複製貼上）

---

## 2. 閉環完備性驗證（通用 Checklist）

以下為任何文件審查均適用的通用核對項目，執行完整審查前必須全部通過。

### 2.1 元資料完整性

- [ ] **【必要】** merge.yaml 含 `document_id` 且格式為 `{TYPE}-{序號}`
- [ ] **【必要】** merge.yaml 含 `type` 欄位，且與資料夾類型代碼一致
- [ ] **【必要】** merge.yaml 含 `title_zh`（繁體中文標題）
- [ ] **【必要】** merge.yaml 含 `version`（格式 `MAJOR.MINOR`）
- [ ] **【必要】** merge.yaml 含 `effective_date`（格式 `YYYY-MM-DD`）
- [ ] **【必要】** merge.yaml 含 `next_review_date`（非空白）
- [ ] **【必要】** merge.yaml 含 `owner`（負責部門或人員）

### 2.2 術語合規性

- [ ] **【必要】** 文件中無「碳排」（應為「排放量」）
- [ ] **【必要】** 文件中無「Scope 1/2/3」（應為「類別 1/2/3」）
- [ ] **【必要】** 文件中無「範圍」作為組織邊界的描述（應為「組織邊界」）
- [ ] **【必要】** 文件中無「調查」「清查」代替「盤查」
- [ ] **【必要】** 文件中無「驗證」「認證」代替「查證」
- [ ] **【必要】** 排放量數據使用 `tCO2e` 單位（非「噸CO2」「公噸碳」）
- [ ] **【必要】** 文件中無「排放因子」（應為「排放係數」）

### 2.3 章節標題格式

- [ ] **【必要】** 所有 H2 heading 使用數字編號（`## 1. 目的`），無中文編號（`## 一、目的`）
- [ ] **【必要】** 所有 H3 heading 使用 X.Y 格式（`### 4.1 申請階段`）
- [ ] 無混用數字編號與中文編號的情況

### 2.4 引文格式

- [ ] **【必要】** 所有交叉引用使用 document_id（非模糊稱謂如「前述文件」）
- [ ] **【必要】** AI 回答引文冒號使用半形 `:` 非全形 `：`
- [ ] **【必要】** 引用的 document_id 均存在於 knowledge/ 目錄
- [ ] merge.yaml 的 `references` 欄位涵蓋文件內所有交叉引用

### 2.5 無佔位符

- [ ] **【必要】** 文件主檔（.md）不含「待補充」「TBD」「TODO」「FIXME」
- [ ] **【必要】** rule.md 不含上述佔位符
- [ ] **【必要】** writer.md 不含上述佔位符
- [ ] **【必要】** reviewer.md 本身不含上述佔位符

---

## 3. 閉環不變量驗證

在審查完畢前，確認以下四項不變量未被破壞：

- [ ] **IV-1** rule.md【必要】條目數 ≤ reviewer.md checkbox 數（reviewer 完整覆蓋 rule）
- [ ] **IV-2** writer.md 章節結構 ⊇ rule.md 必要章節結構（writer 未遺漏任何必要章節）
- [ ] **IV-3** rule.md、writer.md、reviewer.md 三份檔案均無佔位符
- [ ] **IV-4** 三份檔案出現的 document_id 與 merge.yaml 的 `document_id` 欄位一致

---

## 4. 類型特定關鍵字（用於 RC-4 stub 判定）

reviewer.md 必須至少含有其文件類型對應的一個關鍵字，否則判定為 stub。

| 類型 | 必含關鍵字（至少一個）|
|------|---------------------|
| POL  | shall、政策聲明、向下連結 |
| PRO  | RACI、parent_policy、SLA、流程圖 |
| RPT  | 數據年度、總排放量、邊界 |
| STD  | 條款、要求、合規 |
| PLN  | 行動表格、負責人、期限 |
| MTX  | 矩陣、對照、追溯 |
| FRM  | 必填、核准區段、填寫說明 |
| REG  | 表格格式、更新頻率 |
| GDL  | 參考、公式、範例 |

---

## 5. 類型特定審查 Checklist

### 5.1 POL — 政策文件

- [ ] **【必要】** 含「政策聲明」章節，且具體說明 ESG 承諾目標（shall / 應）
- [ ] **【必要】** 向下連結至少一份 PRO（在「相關文件」或「交叉引用」中）
- [ ] **【必要】** 適用範圍明確說明涵蓋的組織單位或設施
- [ ] **【必要】** 政策聲明語氣使用 shall / 應 / 必須（表示義務性）
- [ ] 含高階主管署名或核准記錄

### 5.2 PRO — 程序書

- [ ] **【必要】** merge.yaml 含 `parent_policy` 欄位，指向父 POL document_id
- [ ] **【必要】** 含 RACI 表（負責 R、當責 A、諮詢 C、知會 I）
- [ ] **【必要】** 作業流程有流程圖（Mermaid）或編號步驟清單
- [ ] **【必要】** 各流程步驟有明確的 SLA 或處理時限（若適用）
- [ ] 連結相關 FRM 表單

### 5.3 RPT — 報告文件

- [ ] **【必要】** 說明盤查年度（數據年度為 YYYY 年度）
- [ ] **【必要】** 總排放量依類別 1、類別 2、類別 3 分項列示
- [ ] **【必要】** 明確說明組織邊界（涵蓋法人實體、邊界判斷方法）
- [ ] **【必要】** 排放係數來源（資料庫名稱與版本）有明確標注
- [ ] **【必要】** 所有排放數據標示 tCO2e 單位
- [ ] 含數據品質說明（不確定性評估）

### 5.4 STD — 標準文件

- [ ] **【必要】** 以條款格式呈現要求（編號條款）
- [ ] **【必要】** 每項要求明確說明合規判斷標準
- [ ] **【必要】** 標注適用的 ISO 或法規條款參照

### 5.5 PLN — 計畫文件

- [ ] **【必要】** 含行動表格（行動項目、負責人、完成期限）
- [ ] **【必要】** 每個行動項目有明確的負責人（人名或職稱）
- [ ] **【必要】** 每個行動項目有明確的完成期限（YYYY-MM-DD 或 YYYY-QN）
- [ ] 含進度追蹤機制說明

### 5.6 MTX — 矩陣／對照表

- [ ] **【必要】** 每個排放係數標明追溯來源（原始資料庫、版本、更新日期）
- [ ] **【必要】** 矩陣欄位含活動數據單位與排放係數值
- [ ] **【必要】** 含對照說明，便於查核數據引用的正確性
- [ ] 提供排放量計算公式

### 5.7 FRM — 表單

- [ ] **【必要】** 含填寫說明，說明各欄位用途
- [ ] **【必要】** 必填欄位標注「必填」
- [ ] **【必要】** 含核准區段（至少包含：核准人姓名、職稱、日期）
- [ ] **【必要】** merge.yaml 含 `fields:` 定義所有表單欄位
- [ ] 含表單版本號與修訂日期

### 5.8 REG — 紀錄冊／登錄簿

- [ ] **【必要】** 表格格式定義清楚（欄位名稱、資料型態）
- [ ] **【必要】** 說明更新頻率（每月、每季、每年）
- [ ] 含資料保存年限規定

### 5.9 GDL — 指引

- [ ] **【必要】** 含參考文件清單（ISO 標準、政府公告等）
- [ ] **【必要】** 含計算公式或應用範例（at least 一個）
- [ ] 語氣使用 should / 建議（非強制性）
- [ ] 含適用情境說明

---

## 6. 審查結果記錄

完成文件審查後，reviewer 在 PR/MR comment 中附上以下聲明：

```
審查結果：[通過 / 不通過]
閉環不變量：IV-1 [✓/✗] IV-2 [✓/✗] IV-3 [✓/✗] IV-4 [✓/✗]
未通過項目：（列出具體 checkbox 編號）
建議動作：（修正說明或 "無"）
```

若有任何【必要】checkbox 未勾選，**不得核准合併**。
