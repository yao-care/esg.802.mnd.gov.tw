# Meta-Rule：閉環檔案品質規範

本檔案定義知識庫的合格標準、標記慣例、術語規範與引文格式。所有 rule.md、writer.md、reviewer.md 的產出皆須符合此規範。

---

## 1. 標記慣例

| 標記 | 說明 |
|------|------|
| **【必要】** | 強制要求；reviewer.md 的 checkbox 必須 100% 覆蓋所有【必要】條目 |
| 【建議】 | 優良實踐；不強制但鼓勵遵循 |

**規則：** 若 reviewer.md 的 checkbox 數量少於對應 rule.md 的【必要】條目數，視為不合格（閉環不變量 IV-1）。

---

## 2. rule.md 的合格標準

每份文件類型的 `rule.md` 必須通過以下六項必要條目：

1. **【必要】** 包含「必要章節結構」區段，明列各章節標題與順序
2. **【必要】** 包含「語氣與用詞規範」區段，定義文體要求與禁用詞彙
3. **【必要】** 包含「必要元素」區段，逐條說明文件不可缺少的要素
4. **【必要】** 包含「交叉引用規則」區段，說明與其他文件類型的連結規範
5. **【必要】** 包含「審查重點」區段，供 reviewer 快速核對
6. **【必要】** 所有強制要求使用 **【必要】** 標記，建議事項使用【建議】標記
7. **【必要】** 不含「待補充」「TBD」「TODO」「FIXME」等佔位符

---

## 3. 閉環不變量

閉環系統的四項不可違反的約束，任何修改都不得破壞：

| 編號 | 不變量 |
|------|--------|
| IV-1 | rule.md【必要】條目數 ≤ reviewer.md checkbox 數（reviewer 必須完整覆蓋） |
| IV-2 | writer.md 章節結構 ⊇ rule.md 必要章節結構（writer 不得遺漏 rule 要求的任何章節） |
| IV-3 | 三份檔案均不含「待補充」「TBD」「TODO」「FIXME」等佔位符 |
| IV-4 | 三份檔案中出現的 document_id 必須與對應資料夾的 merge.yaml 保持一致 |

---

## 4. ESG 領域術語規範

使用 ISO 14064-1 及 GHG Protocol 標準術語。以下為強制對照表：

| 正確用語 | 禁用詞 | 說明 |
|---------|--------|------|
| 排放量 | 碳排 | 「碳排」為非正式口語，不得用於正式文件 |
| 類別 1 / 類別 2 / 類別 3 | Scope 1 / Scope 2 / Scope 3 | 繁體中文文件使用中文類別名稱 |
| 組織邊界 | 範圍 | 「範圍」語義模糊，組織邊界指盤查涵蓋的法人實體 |
| 盤查 | 調查、清查 | 溫室氣體盤查為 ISO 14064-1 正式用語 |
| 查證 | 驗證、認證 | GHG 查證（verification）有特定流程意義 |
| tCO2e | 噸CO2、公噸碳 | 標準單位符號，表示公噸二氧化碳當量 |
| 排放係數 | 排放因子 | 「排放因子」為英文 emission factor 直譯，正式中文為「排放係數」 |

【建議】文件首次出現縮寫時，依格式「全稱（縮寫）」標注，如「二氧化碳當量（CO2e）」。

## 5. 章節標題格式

### 5.1 儲存格式（Markdown 原始檔）

章節標題一律使用**數字編號** + Markdown heading：

```markdown
## 1. 目的
## 2. 適用範圍
## 3. 名詞定義
## 4. 作業流程
## 5. 相關文件
## 6. 附件
```

子章節使用「X.Y」格式：

```markdown
### 4.1 申請階段
### 4.2 審核階段
### 4.3 核准與通知
```

### 5.2 輸出格式（HTML 渲染）

Build 時由 `build.js` 的 `renderMarkdownToHtml` 自動將數字編號轉換為中文編號：

- `## 1. ` → `一、`
- `## 2. ` → `二、`
- `## 3. ` → `三、`
- `### 4.1 ` → `（一）`
- `### 4.2 ` → `（二）`

### 5.3 禁止事項

- **【必要】** 禁止在 Markdown 中直接使用「一、」「二、」中文編號作為 heading
- **【必要】** 禁止混用數字編號與中文編號

---

## 6. 引文格式

### 6.1 文件內交叉引用（Markdown 原始檔）

引用其他文件時使用 document_id：

- 正確：「依 PRO-GHG-INV 辦理」
- 正確：「參照 POL-ESG-001 第 3 節」
- 正確：「填寫 FRM-GHG-001 溫室氣體盤查紀錄表」

**【必要】** 引用的 document_id 必須存在於 knowledge/ 目錄下，且與 merge.yaml 的 `document_id` 欄位完全一致。

### 6.2 AI 回答引文格式（system prompt 規範）

AI 回答中的引文使用以下格式：

```
[來源:文件編號#章節]
```

規則：

- **【必要】** 冒號使用半形 `:` （U+003A），禁止使用全形 `：`（U+FF1A）
- **【必要】** 文件編號使用 knowledge/ 中的實際 document_id
- 章節使用數字格式（如 `#4. 作業流程`）
- 一個回答可包含多個引文

### 6.3 防護機制

即使 AI 未遵循上述格式，`assistant.html` 的 `autoLinkDocKeys` 機制會自動偵測回答中出現的所有已知 document_id 並建立連結。此機制不依賴 AI 的格式遵循度。

---

## 7. 交叉引用規則

各文件類型的連結方向與強制要求：

| 文件類型 | 必要連結 | 說明 |
|---------|---------|------|
| POL | **【必要】** 向下連結至少一份 PRO | 政策宣告必須有對應程序書實作 |
| PRO | **【必要】** 引用 `parent_policy`（POL document_id） | 程序書必須說明其依據的政策 |
| PRO | 【建議】連結相關 FRM | 程序書應說明使用哪些表單 |
| RPT | 【建議】引用數據來源 MTX 或 FRM | 報告應說明數據的計算依據 |
| MTX | **【必要】** 標明追溯來源 | 排放係數矩陣必須標注數據出處 |
| FRM | 【建議】連結所屬 PRO | 表單應說明在哪個程序中使用 |

---

## 8. 版本與審查管理

- **【必要】** 每份文件的 merge.yaml 必須含 `version`、`effective_date`、`next_review_date` 欄位
- **【必要】** `next_review_date` 不得空白，ESG 報告類文件建議每年審查一次
- 【建議】重大修訂（major version）應同步通知相關程序書維護者
- **【必要】** 版本號格式為 `MAJOR.MINOR`，如 `1.0`、`2.1`
