# MTX 類型規範 / MTX Type Specification

MTX（Matrix）為對照矩陣文件，用於呈現多維度關係，例如法規條款對應控制措施、利害關係人對應重大主題、排放源對應邊界分類等。MTX 必須以結構化表格呈現，並可追溯至來源文件。

## 必要章節結構

1. 【必要】矩陣目的與範圍 — 說明此矩陣解決什麼問題、涵蓋哪些維度、適用哪些讀者
2. 【必要】行／列定義 — 明確定義矩陣的行（row）與列（column）各代表什麼；說明儲存格的內容格式（如：Y/N、狀態代碼、引用文件 ID）
3. 【必要】資料來源 — 列出矩陣中每個維度的來源文件（含文件識別碼）
4. 【必要】更新頻率與維護 — 說明何時需要更新矩陣（如：法規修訂、新增據點、年度審查）；指定維護責任人

## 語氣與用詞規範

- 矩陣中的儲存格內容保持簡潔（代碼、Y/N、或簡短說明）；詳細說明置於備註欄或附件
- 行列標題使用名詞，不使用動詞
- 狀態代碼需在文件開頭或附表中統一定義（如：C=合規、NC=不合規、NA=不適用）
- 避免在儲存格中放入超過 50 字元的文字

## 必要元素

- 【必要】表格格式（Markdown table）：矩陣本體以 Markdown 表格呈現，表頭清晰標示行列維度名稱
- 【必要】追溯至來源文件：矩陣中每個維度來源必須在「資料來源」章節中明確引用對應文件識別碼
- 【必要】儲存格值定義：若使用代碼（Y/N/C/NC/NA 等），必須提供代碼說明表
- 【必要】最後更新日期：標示於文件標頭或矩陣目的章節

## 交叉引用規則

- 法規對應矩陣的行維度（法規條款）須引用 STD 文件
- 控制措施維度須引用對應的 POL 或 PRO 文件
- 利害關係人矩陣若涉及重大性評估，須引用 RPT 中的重大性分析章節
- 若矩陣作為 PRO 的附錄，須在 PRO 文件中以附錄形式引用此 MTX

## 審查重點

- M1 **表格格式**：是否以 Markdown table 呈現；表頭是否清晰；是否所有儲存格均有值（空白需以 `—` 或 `NA` 填入）
- M2 **來源追溯**：矩陣每個維度是否均有對應的來源文件識別碼；引用格式是否正確
- M3 **代碼一致性**：全文使用的狀態代碼是否一致；代碼說明表是否存在且完整
- M4 **更新機制**：是否指定維護責任人；是否說明觸發更新的條件

## 類型特定關鍵字

`矩陣`、`對照`、`追溯`、`行列定義`、`來源文件`、`狀態代碼`
